# RETRACK v1.0.0 — mốc mã nguồn phát hành

## Phạm vi

Chốt phiên bản tích hợp hiện tại từ `develop` vào `main`, kèm cấu hình triển khai frontend trên Vercel. Đây là mốc mã nguồn phục vụ đồ án; không đồng nghĩa đã nghiệm thu toàn bộ nghiệp vụ hoặc triển khai production.

- Frontend React/Vite, backend ASP.NET Core và mobile giữ kiến trúc hiện tại.
- Bổ sung cấu hình Vercel cho `/api`, fallback React Router, mẫu biến frontend và hướng dẫn triển khai.
- Chọn `main` làm Production Branch, `develop` làm nhánh tích hợp; dùng PR để đưa thay đổi vào bản phát hành.
- Node frontend dùng nhánh 24; `.nvmrc` dành cho công cụ quản lý Node tương thích, dashboard Vercel cũng cần chọn `24.x`.
- Không gộp chỉnh sửa local chưa commit tại `LiquidationRules.cs`, không thay secret, cấu hình PostgreSQL local, không chạy migration/seed hoặc deploy dịch vụ.

## Biến môi trường và cập nhật tự động

Cấu hình thật của backend, frontend và mobile được quản lý riêng. Các file `.env.example` chỉ là mẫu, không chứa secret. Vercel lưu biến frontend ở Settings > Environment Variables, giữ lại cho các lần deploy tiếp theo.

Axios dùng `/api`; địa chỉ backend nằm trong `frontend/vercel.json`, không đọc `VITE_API_URL`. Sau khi liên kết GitHub, commit mới vào `main` có thể tự kích hoạt build/deploy. Thay biến Vite cần một bản build mới; không cần tạo lại project.

## Kiểm chứng và giới hạn

- Cấu hình frontend: `npm ci`, lint, build và kiểm tra JSON/đường dẫn API đạt. Lint có 7 cảnh báo có sẵn; build có cảnh báo chunk lớn.
- Backend: `dotnet restore backend/Retrack.sln` và `dotnet build backend/Retrack.sln --no-restore` đạt, 0 lỗi/0 cảnh báo. Không chạy PostgreSQL tests trong lượt phát hành này vì chưa thiết lập hai biến tới database test được xác minh.
- Kết nối HTTP tới backend Azure từ môi trường kiểm tra timeout sau 20 giây. Chưa xác định lỗi mạng/hạ tầng; không kết luận API đang hoạt động chỉ từ frontend build.
- Chưa deploy vào tài khoản Vercel, chưa chạy E2E trên domain công khai và chưa nghiệm thu mọi role cho mốc phát hành này.
- Backend đang được cung cấp bằng HTTP. Trước khi sử dụng tài khoản/dữ liệu thật, cần HTTPS hợp lệ tại Azure rồi cập nhật đích proxy.
- Kiểm thử tài chính/tồn kho trên PostgreSQL cần đúng database test và quy trình riêng; không dùng database chung để kiểm thử phát hành.
- Hạn chế nền tảng/backend/provider và phụ thuộc các role vẫn theo README và hồ sơ bàn giao hiện có; không suy diễn tag `v1.0.0` là chứng nhận production.

## Triển khai

Làm theo [hướng dẫn frontend Vercel](../deploy-frontend-vercel.md). Sau khi merge, đối chiếu branch/commit của deployment. Chưa có tag/release trước đó không thay thế việc review diff của `develop -> main`.
